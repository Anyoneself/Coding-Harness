## Coding-Harness Specification Rules

- Read the applicable `AGENTS.md` files and relevant documents under `docs/pm/` before finalizing the specification.
- Write the feature artifacts in Chinese while preserving code identifiers, protocol names, formulas, and established English terms.
- Link the feature to an existing product task ID when one exists. Do not copy the whole product roadmap into the feature spec.
- Every user story must include observable Given/When/Then acceptance scenarios suitable for `tests/features/`.
- State failure behavior, compatibility boundaries, security constraints, and out-of-scope behavior explicitly.
- Do not modify production code, tests, README, or unrelated project documents during specification.
