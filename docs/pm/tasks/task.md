# Coding Harness 产品任务

## 使用约定

- `【√】`：任务已完成，并满足当前验收口径。
- `【】`：任务未完成；只有依赖任务完成后才进入实现。
- `（依赖: 无）`：可以独立实施。
- 任务按依赖关系推进，不绑定日期、周期或人员配置。

## 迭代一：可持续执行底座

产品形态：用户可以在 Web 中创建持续运行的只读代码任务；页面断开不影响执行，任务过程可重放、可中断并可从稳定点恢复。

- 【√】T0 建立 Workspace、Thread、Turn、Item 和 Checkpoint 统一执行领域模型，明确任务状态与实体关系（依赖: 无）
- 【√】T1 建立服务端 Turn 调度与单 Thread 串行约束，使任务生命周期脱离页面连接（依赖: T0）
- 【√】T2 建立版本化事件持久化、SSE 推送与断线重放，保证事件连续、有序且不重复（依赖: T1）
- 【√】T3 建立主动中断、稳定 Checkpoint、异常运行识别与恢复机制，避免从头重复任务（依赖: T1、T2）
- 【√】T4 建立工作区路径、敏感文件和命令默认拒绝边界，模型不能直接改变执行状态或绕过 Harness（依赖: T0）
- 【√】T5 接入 DeepSeek Provider、执行预算、用量记录以及 SQLite/PostgreSQL 执行仓储契约（依赖: T1、T3、T4）

迭代退出条件：任务断线后仍可完成；重连后事件可完整恢复；异常执行不会显示为成功；同一任务不会重复运行；越界读取和未授权命令被拒绝。

## 迭代二：安全交付与双端首发

产品形态：用户可以从 Web 工作台或 CLI 选择云端或本地模型，在明确权限下完成代码探索、修改、验证和审查；两端共享同一执行状态、权限策略和事件协议。

### 多模型接入

- 【】T6 定义 ProviderRegistry、ProviderDescriptor、ProviderCapabilities 和统一 ModelEvent 契约，隔离供应商协议与 Harness 执行逻辑（依赖: T5）
- 【】T7 改造 DeepSeek Adapter 以通过统一 Provider 契约，并保留流式输出、用量、取消和错误语义（依赖: T6）
- 【】T8 实现 OpenAI 原生 Adapter，映射文本、工具调用、流式事件、用量、停止原因和错误（依赖: T6）
- 【】T9 实现 Anthropic 原生 Adapter，映射 content block、tool use、流式事件、用量、停止原因和错误（依赖: T6）
- 【】T10 实现 OpenAI-compatible 本地模型 Adapter，支持自定义 base URL、模型发现和能力显式声明（依赖: T6）
- 【】T11 建立 Provider 配置、凭据引用、模型选择和 Turn 能力快照，禁止在 Turn 中静默切换 Provider 或模型（依赖: T7、T8、T9、T10）
- 【】T12 建立 Provider 契约测试，覆盖流式文本、工具提议、取消、限流、畸形响应、用量和上下文超限（依赖: T7、T8、T9、T10）

### 工具、权限与恢复

- 【】T13 定义 ToolDefinition、ToolInvocation、ToolResult、ToolRegistry 和统一工具状态机，Agent 只能提出工具调用（依赖: T6）
- 【】T14 实现受工作区边界约束的文件读取、目录遍历和文本搜索工具（依赖: T13、T4）
- 【】T15 实现带内容基线校验的补丁、创建、删除和重命名工具，所有写入产生结构化结果（依赖: T13、T14）
- 【】T16 实现只读 Git 查询和受控命令执行工具，统一处理超时、退出码、输出截断和进程终止（依赖: T13）
- 【】T17 建立 allow、ask、deny 工具策略和风险分级，路径、参数、网络与权限范围参与决策（依赖: T13、T4）
- 【】T18 建立结构化审批、action digest、单次授权与当前 Turn 授权，参数或作用域变化后旧审批失效（依赖: T17）
- 【】T19 接入可信 SandboxAdapter，限制文件系统、网络、子进程和环境变量；不可用时命令能力保持关闭（依赖: T16、T17）
- 【】T20 建立 call_id 幂等、工具结果核验和不确定副作用恢复机制，禁止盲目重试写操作（依赖: T15、T16、T18、T19）
- 【】T21 将完整工具结果、审批结果和稳定点写入 Item、事件与 Checkpoint，确保中断恢复不重复副作用（依赖: T3、T20）

### 变更与验证

- 【】T22 在 Turn 起止记录 Git 与文件基线，区分任务开始前已有改动和 Agent 新改动（依赖: T15、T21）
- 【】T23 建立并发修改检测，基线变化时停止覆盖并输出可操作的冲突信息（依赖: T22）
- 【】T24 生成 ChangeSet、文件变化列表和完整 Diff，大型内容以不可变 Artifact 按需读取（依赖: T22、T23）
- 【】T25 建立 Verification 记录，保存测试、静态检查和构建命令的状态、退出码、耗时与输出摘要（依赖: T16、T21、T24）
- 【】T26 收紧 Turn 完成语义：最终消息、ChangeSet 和 Verification Summary 齐备后才能完成，只读任务允许空 ChangeSet（依赖: T24、T25）

### Web 与 CLI

- 【】T27 冻结 Turn、事件、审批、ChangeSet、Verification 和 Provider 相关 API 与 Schema，作为 Web/CLI 共同协议（依赖: T11、T12、T21、T26）
- 【】T28 完善 Web 工作台的执行流、审批、Files Changed、Diff、Verification、Provider 选择和错误定位视图（依赖: T27）
- 【】T29 实现 CLI 的 `exec`、`resume`、`inspect`、审批、中断以及 Provider/模型选择能力（依赖: T27）
- 【】T30 提供稳定 JSON Lines、结构化退出码和 SIGINT 处理，机器输出不得混入进度日志（依赖: T29）
- 【】T31 建立 Web/CLI 一致性契约测试，验证两端对同一 Turn 的状态、审批、事件和交付结果一致（依赖: T28、T30）

### 评估与首发门禁

- 【】T32 建立可复现的真实 Coding Task 数据集，包含功能、修复、只读、安全、恢复和越界攻击案例（依赖: T26）
- 【】T33 建立逐任务 Trace、断言、ChangeSet、Verification、Provider 版本和成本结果记录（依赖: T12、T24、T25、T32）
- 【】T34 建立跨 Provider 回归与发布门禁，安全用例必须零放行，能力不兼容必须在副作用前失败（依赖: T12、T31、T33）
- 【】T35 完成 Web 与 CLI 双入口首发验收，确保核心代码任务可执行、可控制、可恢复、可审查（依赖: T31、T34）

迭代退出条件：四类 Provider 通过统一契约；所有工具动作经过策略与审批；重复调用不重复产生副作用；并发编辑不被静默覆盖；Web 与 CLI 状态一致；交付结果包含可审查变更和真实验证证据；安全回归不存在越界或审批绕过。

## 迭代三：可配置内测产品

产品形态：不同仓库可以沉淀项目规则和复用流程；多 Provider 可观测、可治理并可显式路由；CLI 可以稳定进入批处理和 CI；质量、成本和用户反馈形成回归闭环。

- 【】T36 支持分层加载 `AGENTS.md`，实现项目指令优先级、来源追踪和安全规则不可覆盖（依赖: T35）
- 【】T37 建立 Context Snapshot 与裁剪策略，保留当前目标、安全约束和来源信息，优先裁剪可重读内容（依赖: T36）
- 【】T38 支持 Skill 元数据发现、任务匹配和按需加载，Skill 不获得额外工具权限（依赖: T37）
- 【】T39 建立 Provider 健康状态、模型目录、能力与成本信息，并提供可解释的显式路由规则（依赖: T34）
- 【】T40 为 CLI 增加版本化输出 Schema、批处理和 CI 模式，非交互环境遇到 ask 时安全失败（依赖: T30、T35）
- 【】T41 建立覆盖模型、工具、权限、执行、验证和交付阶段的结构化日志、Trace 与指标（依赖: T33、T35）
- 【】T42 建立按 Turn 归集的 Token、模型调用、工具调用、执行时长和费用监控与预算告警（依赖: T39、T41）
- 【】T43 记录 Prompt、模型、Provider 配置、工具、策略、工作流和数据集版本，支持结果归因与回放（依赖: T33、T41）
- 【】T44 建立用户接受、需要修改和无效反馈入口，并将高频失败转化为评估案例（依赖: T28、T33）
- 【】T45 建立版本化离线回归与在线反馈闭环，模型、Prompt、工具或策略变更必须产生可比较报告（依赖: T42、T43、T44）
- 【】T46 完成内测验收，确认项目规则、Skill、Provider 治理、自动化、可观测性和反馈闭环可在真实仓库持续使用（依赖: T38、T39、T40、T45）

迭代退出条件：上下文来源可解释；Skill 按需加载且不提升权限；Provider 选择与路由可追溯；CLI 可安全进入 CI；敏感信息和隐藏推理不进入日志；任何关键版本变化都有可复现回归结果；用户反馈能够进入产品改进流程。
