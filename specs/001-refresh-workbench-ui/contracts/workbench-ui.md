# Workbench UI Contract

本 Contract 定义参考图升级后用户可观察的稳定界面行为。它不新增 HTTP 接口，也不替代现有后端 Schema。

## 1. 稳定术语

- `Workspace`: 当前真实项目与执行边界。
- `Thread`: 界面中的“任务”。
- `Turn`: 一次任务执行。
- `Event`: 可重放的公开执行事件。
- `Inspector`: 按需展示 Event 或 Turn 信息的覆盖式区域。

界面不得使用 `Session`、`Conversation` 或 `Run` 替代这些业务概念。

## 2. 顶部导航

| 可见名称 | 动作 | 结果 |
|----------|------|------|
| 工作台 | 选择主工作台 | 关闭 Inspector，保留当前任务与执行状态 |
| 执行事件 | 查看公开事件 | 打开 Inspector 并选择事件标签 |
| Turn | 查看 Turn 信息 | 打开 Inspector 并选择 Turn 标签 |

不得显示没有真实目标视图的评估、工具、搜索、设置或账户控件。

## 3. 任务导航

### 必须提供

- `新建任务` 按钮。
- 按时间分组的最近任务。
- 当前任务的明确选中状态。
- 每个任务的标题和公开状态。
- 当前唯一 Workspace 的项目显示名。
- 模型连接就绪、未配置或连接中状态。

### 运行中约束

当当前 Turn 正在运行时：

- 新建任务不可执行。
- 切换到其他任务不可执行。
- 移除任务不可执行。
- 当前任务仍可观察。
- 输入器主操作变为中断。

禁用状态必须可感知，不能只依赖点击后静默返回。

## 4. 空任务入口

当无公开消息且没有实时 Assistant 时，主画布必须显示：

- Coding-Harness 品牌标识。
- 标题“你想让我们在 Coding-Harness 中构建什么？”。
- 真实项目显示名。
- 当前模型显示名或明确的读取/未就绪状态。
- 唯一任务文本输入。
- 唯一发送主操作。

不得显示：

- 静态伪造的项目或分支。
- 可选择模型的视觉暗示。
- 功能介绍卡片。
- 无目标行为的装饰按钮。

## 5. 输入器

### 稳定行为

- `Enter`: 发送非空任务。
- `Shift+Enter`: 输入换行。
- 输入为空: 不提交。
- 模型未就绪: 打开现有 API Key 配置流程。
- Turn 运行中: 主操作显示“中断任务”并请求中断。
- 输入上限: 20,000 字符。

### 稳定上下文

- 项目名称来自公开 Workspace 路径。
- 执行边界显示为 Workspace，不伪造 Git 分支。
- 模型名称来自公开配置，只读展示。
- 发送与中断使用同一个固定尺寸和位置。

## 6. 执行阅读态

首条用户消息进入当前 Thread 后：

- 空状态标题退出主要阅读区域。
- 当前公开消息在同一主画布显示。
- 输入器移动到底部并收敛到阅读宽度。
- 流光背景降低对比度但仍保持品牌连续性。
- 流式增量只显示公开 Assistant 内容。
- 错误、终态和中断使用可理解文字，不显示内部响应正文。

## 7. Inspector

- 默认关闭。
- 桌面与移动均以覆盖方式打开，不永久压缩主画布。
- 事件标签按递增序号显示公开事件。
- 未知事件显示原始公开类型，不猜测语义。
- Turn 标签只显示现有公开状态、Turn ID、事件序号、事件数量和公开 Token。
- 关闭后当前任务、消息、输入草稿和 ExecutionState 保持不变。
- 必须提供“关闭执行检查器”的可访问操作。

## 8. 配置与失败状态

| 条件 | 用户可见结果 |
|------|--------------|
| 配置未就绪 | 打开现有 API Key 对话框；密钥不进入浏览器持久化 |
| 配置读取失败 | 显示连接错误；发送不得表现为成功 |
| Workspace/Thread/Turn 创建失败 | 当前任务进入连接失败状态并显示公开安全提示 |
| SSE 请求失败 | 当前执行进入失败状态 |
| SSE 非终态结束 | 当前执行进入连接失败状态；部分回答不持久化为成功 |
| 中断请求失败 | 保留当前执行并显示“中断请求失败” |
| 背景资源失败 | 使用静态冰蓝画布，全部业务操作仍可用 |

## 9. Responsive Contract

### 1680×941

- Sidebar 固定可见。
- 顶部导航居中。
- 空状态标题和宽输入器均在首屏。
- Inspector 默认关闭，打开后覆盖右侧主画布。

### 1024×768

- Sidebar 保持可见。
- 主标题、输入器和主要操作不被推出首屏。
- Inspector 覆盖显示。

### 390×844 与 320px 最小宽度

- Sidebar 与 Inspector 默认关闭并分别由独立控件打开。
- 页面无横向滚动。
- 顶部三个真实视图可访问。
- 项目名、模型名和任务名截断或换行，不挤压主操作。
- 输入器、发送或中断按钮、配置对话框均可完整操作。

## 10. Accessibility Contract

- 图标按钮具有 `aria-label`，不熟悉的图标同时提供 `title`。
- 活动导航使用 `aria-current`，Inspector 标签使用 tab 语义。
- Inspector 通过 `aria-hidden` 或等价语义准确表达可见状态。
- 异步错误使用适当的 alert/status 语义。
- 流式回答使用克制的 live region，不逐 token 重复播报。
- 键盘焦点始终可见；抽屉和对话框有明确退出路径。
- 状态除颜色外还使用文字、图标或位置表达。
- `prefers-reduced-motion: reduce` 下停止非必要动画，不改变功能。

## 11. HTTP 与存储兼容

本功能继续消费现有接口：

```text
GET  /api/config
POST /api/config/api-key
POST /api/workspaces
POST /api/workspaces/{workspace_id}/threads
POST /api/threads/{thread_id}/turns
GET  /api/turns/{turn_id}/events/stream
POST /api/turns/{turn_id}/interrupt
```

本功能不改变 localStorage Key、数据字段、最多 30 个任务限制或敏感字段拒绝规则。
