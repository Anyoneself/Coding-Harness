# 自动化质量门禁

先按变更风险选择默认门槛，再结合仓库基线调整。任何下调都必须在编码前记录理由和补偿措施；不得在看到失败结果后降低阈值。

## 风险分级与默认指标

| 等级 | 典型变更 | 变更行覆盖率 | 变更分支覆盖率 | 目标变异分数 |
| --- | --- | ---: | ---: | ---: |
| 低 | 局部、可逆、无持久化和外部契约 | >= 85% | >= 75% | >= 60% |
| 中 | 共享业务规则、API、持久化、外部适配器 | >= 90% | >= 85% | >= 70% |
| 高 | 权限、安全、迁移、并发、资金、不可逆写入 | >= 95% | >= 90% | >= 80% |

以上是缺少项目标准时的起点，不替代更严格的仓库要求。所有等级均要求全量测试通过、目标模块总覆盖率不下降、关键存活变异逐项审查。只统计覆盖率不足以证明质量，应同时检查断言有效性和变异结果。

## 基础门禁

每次生产代码变更均应发现并执行仓库已有的以下检查：

| 检查 ID | 检查 | 目的 |
| --- | --- | --- |
| QG-01 | 新增/定向测试 | 快速证明需求与回归行为 |
| QG-02 | 全量单元和集成测试 | 发现跨模块回归 |
| QG-03 | Gherkin 场景或其可执行映射 | 验证用户可观察验收条件 |
| QG-04 | 行与分支覆盖率 | 发现未执行路径 |
| QG-05 | 目标代码变异测试 | 验证测试能识别错误实现 |
| QG-06 | Lint、格式检查、导入检查 | 维持静态一致性 |
| QG-07 | 类型检查或编译 | 验证静态契约和构建正确性 |
| QG-08 | Diff 中密钥与敏感信息检查 | 防止凭据和隐私数据进入仓库 |
| QG-09 | 打包、启动或最小 smoke | 验证交付物可装配运行 |
| QG-10 | 文档、Schema、示例一致性 | 防止接口与使用说明漂移 |

若仓库没有对应工具，不能声称该项通过。应选择轻量替代验证，或在确有持续收益时提出新增依赖；新增依赖仍受用户授权和仓库规范约束。

## 条件门禁

仅在风险相关时启用，但一旦适用就进入阻断条件：

| 领域 | 自动化检查 |
| --- | --- |
| HTTP/API/SSE/CLI | Schema 兼容、状态码/事件顺序、错误格式、分页、幂等、旧客户端回归 |
| 数据库 | 迁移前后测试、回滚或恢复演练、约束/索引、事务、N+1、并发写入 |
| 安全与权限 | SAST、依赖漏洞、路径穿越、注入、越权、敏感日志、危险命令参数 |
| 外部依赖 | 超时、重试上限、熔断/降级、限流、幂等、响应畸形和脱敏 |
| 并发与异步 | 竞态、取消、重复投递、顺序、资源释放和压力下稳定性 |
| 性能 | 基准、P95/P99 延迟、吞吐、内存/CPU、查询数量和退化阈值 |
| 前端 | 类型/构建、关键流程 E2E、可访问性、响应式布局、视觉回归 |
| Agent/Harness | 模型替身、工具白名单与确认、结构化参数、提示注入、循环上限、Token/成本预算、流式事件、会话恢复 |
| 可观测性 | 请求/会话关联、阶段与耗时、失败状态、指标、Trace、告警和日志脱敏 |
| 发布 | 配置校验、功能开关、灰度、向后兼容、回滚和健康检查 |

## 变异测试执行规则

- 只对本次变更及其直接关键依赖执行定向变异，避免无边界地消耗时间。
- 优先扰动条件边界、权限判断、状态转换、异常分支、重试次数和持久化副作用。
- 等价变异可排除，但必须说明为何行为等价。
- 存活的非等价变异意味着测试缺口：补充测试或修正不可测设计，然后重新运行。
- 工具不可用时，至少执行关键规则的人工变异抽样；高风险变更不能仅以“未安装工具”为由跳过。

## 失败和不稳定测试

- 新失败由本次变更引入时立即阻断并修复。
- 发现既有失败时，用未修改基线或最小复现区分责任，并在交付中列明命令和错误。
- 不通过无限重跑掩盖 flaky test。先保存首次失败证据，再定位时间、随机数、共享状态、并发或外部依赖。
- 跳过测试、降低断言、排除覆盖率或放宽阈值都属于质量契约变更，必须在编码前有依据，不能作为临时过门手段。

## 推荐执行顺序

先运行最快且定位清晰的检查：定向单元测试、Lint/类型检查、相关集成测试；随后运行覆盖率、变异测试、条件门禁和全量回归。具体命令必须来自仓库配置、CI 或官方工具帮助，执行结果写回质量契约。
