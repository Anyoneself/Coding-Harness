# React 实现与前端质量

本文件用于组件架构、状态管理、性能、可访问性、测试和浏览器验收。规则按风险应用，不为简单
界面强行增加 Provider、抽象层或通用组件库。

## 1. 组件与状态

- 页面组件负责编排稳定区域，领域归约与持久化逻辑留在 `domain/`，HTTP/SSE 留在 `api/`。
- 状态尽量贴近拥有者；多个兄弟区域确实共享时再上移或使用 Provider。
- 复杂组件使用组合拆分结构，避免 `isCompact`、`isEmpty`、`isRunning`、`isMobile` 等多个
  布尔参数组合出隐蔽界面模式。
- 当两种模式拥有不同结构或行为时，提供明确变体组件或具名入口，不在 JSX 中堆叠条件。
- 不在组件函数内部定义子组件；稳定的静态 JSX 和常量移出重复渲染路径。
- 派生值在渲染期间计算，不用 Effect 同步可计算状态。
- Effect 只连接外部系统；用户操作逻辑放在事件处理器中。

## 2. 异步与性能

- 独立请求并行启动，避免可消除的串行等待。
- 重资源只在功能被使用时加载；直接导入使用模块，避免无边界 barrel import 扩大包体。
- localStorage 数据保持最小、带版本并在边界解析；不要在每次渲染中重复读取。
- 对频繁更新的 SSE 数据按语义归约，避免重复事件触发重复文本追加。
- 列表超过约 50 项时评估虚拟化或 `content-visibility`，但不要提前为小列表引入复杂依赖。
- 不在渲染阶段读取布局；需要测量时集中 DOM 读取与写入，防止布局抖动。
- 输入器每次按键的更新路径必须廉价；昂贵预览使用延迟值或隔离组件。
- 动画只修改合成友好的属性，不使用 `transition: all`。

## 3. 可访问性与交互

- 优先使用语义 HTML：操作用 `button`，导航用链接，表单有 label 或可访问名称。
- 图标按钮提供 `aria-label` 和 `title`；装饰图标设置 `aria-hidden="true"`。
- 使用 `:focus-visible` 提供清楚焦点，不无替代地移除 outline。
- 复合控件使用 `:focus-within` 表达整体焦点，浮层不能遮住当前焦点元素。
- 异步状态与错误使用适当的 `aria-live`，避免每个流式 token 都触发重复播报。
- 颜色不是唯一状态编码，同时使用文字、图标、形状或位置。
- 触控目标尺寸稳定；拖动、悬停和手势功能必须有点击与键盘替代。
- 不禁用缩放，不阻止粘贴，不在移动端滥用自动聚焦。

## 4. 稳定布局

- 固定格式区域使用 Grid、Flex、`minmax()`、`aspect-ratio` 或明确尺寸，避免内容改变时跳动。
- Flex 文本子项设置 `min-width: 0`，并为项目名、模型名、路径和错误信息设计截断或换行。
- 图片声明尺寸，首屏关键资源预加载，非关键资源延迟加载。
- 抽屉和模态框使用 `overscroll-behavior: contain`；全屏区域考虑安全区。
- 桌面、窄桌面和移动布局由 CSS 响应式规则决定，不依赖 JavaScript 持续测量视口。

## 5. 测试策略

### 5.1 行为测试

- 先覆盖用户可观察行为：创建任务、切换任务、发送、中断、断流、恢复、配置失败和移动导航。
- Testing Library 通过角色、名称和可见文本选择元素，不依赖内部 class 或组件结构。
- SSE、时间、网络和 localStorage 使用可替换依赖，不访问公网或真实模型。
- 缺陷测试先证明旧行为失败，再实现修复。

### 5.2 浏览器验收

动态应用使用“侦察后操作”：

1. 启动真实前后端或可代表生产构建的本地服务。
2. 导航后等待应用稳定，再检查 DOM、控制台和网络错误。
3. 截取桌面与移动截图，确认内容真实渲染，而不是只验证选择器存在。
4. 走通键盘路径和主要交互，再检查运行中、错误、空数据与长内容。
5. 检查 reduced-motion、焦点、溢出、遮挡和布局漂移。

不要只用像素截图代替行为断言，也不要只用单元测试代替视觉检查。

## 6. 交付门槛

- `npm test`
- `npm run typecheck`
- `npm run build`
- 浏览器控制台无新增错误或未处理 Promise rejection。
- 视觉或布局改动在 `1440×900` 与 `390×844` 无横向溢出、遮挡或不可达操作。
- 受影响状态完整验收；未受影响状态依靠现有行为测试和一次关键路径回归，不扩大修改范围。
- 视觉改动完成删减式截图复盘；事件与消息改动完成长文本和高频事件检查。

## 7. 上游启发

- Vercel `react-best-practices`：消除异步瀑布、控制包体、减少无效重渲染和稳定客户端性能。
- Vercel `composition-patterns`：优先组合、显式变体与清晰状态所有权。
- Vercel `web-design-guidelines`：语义、焦点、表单、内容韧性、动效和响应式质量。
- Anthropic `webapp-testing`：真实浏览器中的侦察、操作、截图和日志检查。

这些原则按当前 React/Vite 架构筛选，不引入本仓库未使用的 Next.js 或服务端组件约束。
